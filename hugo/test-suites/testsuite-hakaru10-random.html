Random numbers

Hakaru10 Embedded probabilistic domain-specific language Hakaru10 draws its random numbers from the StdGen of the Haskell package random-1.0.1.1, seeded with mkStdGen 17 (Metropolis.hs:858) and threaded through the chain state (Metropolis.hs:166, 204-210). Porting that generator, bit for bit, lets the tests of (aux hakaru10) replay upstream's chains exactly: the samples recorded in the Haskell sources are regression oracles, not merely statistical targets.

The generator is Lennart Augustsson's transliteration of L'Ecuyer's portable combined generator for 32-bit computers: two multiplicative congruential generators with moduli 2147483563 and 2147483399, computed with Schrage's method so that no product exceeds 2³¹. Each next answers z ∈ [1, 2147483562]. An Int in a range of size k folds n = ⌈log k / log b⌉ of them, b = 2147483561, as

acc₀ = 1, accᵢ₊₁ = zᵢ₊₁ + b · accᵢ, x = l + (accₙ mod k)

and a Double is an Int64 drawn this way over the whole 64-bit range, n = 3, masked to its 53 low bits and divided by 2⁵³. Upstream's Integer arithmetic makes acc₃ a number of about 93 bits; since 2⁶³ and 2⁶⁴ are multiples of 2⁵³, only

acc₃ mod 2⁵³, (z + b · acc) mod 2⁵³ = (z + ((h b) mod 2²⁶) · 2²⁷ + ℓ b) mod 2⁵³, acc = h · 2²⁷ + ℓ

matters, and the port keeps every intermediate below 2⁵⁹, a fixnum on a 64-bit CHICKEN, instead of allocating bignums at each draw. The bignum reading of the Haskell code is kept as the oracle stdgen-double/reference.

The engine never threads a generator: it draws from an rng source, a record holding a mutable state and the procedures rng-double! (Haskell's randomR (lo,hi) :: Double, a closed interval) and rng-integer! (randomR (lo,hi) :: Int, inclusive). Upstream never rolls the generator back when a proposal is rejected (Metropolis.hs:904-906), so a source that only moves forward is faithful; rng-source-copy replays one.

Two optional sources replay nothing upstream: L'Ecuyer's MRG32k3a Good parameters and implementations for combined multiple recursive random number generators, Operations Research 47(1), 1999, period ≈ 2¹⁹¹, and an adapter over CHICKEN's (chicken random). The latter has caveats: its WELL512 state is global to the process, so the adapter cannot be copied; an all-zero seed is a fixed point of the generator and pseudo-random-integer then never returns (the retry loop of random_uniform in runtime.c, chicken-core main rev 55615603), so the adapter rejects it; a seed is read in whole 8-byte words only (C_set_random_seed, same file and revision), so the adapter pads it; pseudo-random-real can answer 1.0, which the adapter redraws; and the startup seed comes from the clock.
