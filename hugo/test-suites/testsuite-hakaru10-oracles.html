One model, three interpretations

A Hakaru10 model is a value of the State monad of (aux category state), whose state is the chain: Model a = MCMCM (SExp a) (Syntax.hs:82) and MCMCM a = State MCState a (Metropolis.hs:200). dist, diracN and if_ are models, and do/monad, ← and return combine them as Haskell's do does:

(do/monad
  (← x (dist d args))
  (diracN e)
  (if_ test then-model else-model)
  (return x))

Running a model creates its nodes in bind order, and if_ builds both branches, the inactive one first, as upstream's ifnode does (Metropolis.hs:641-686). condition and lift are not models: conditioning makes an observed distribution (Syntax.hs:174-193), and lifting is pure (Syntax.hs:99-116).

The three interpretations are:

  • the build of mcmC: the model runs once on a fresh chain, as upstream's initial_step' runs it (Metropolis.hs:872-880), and incremental Metropolis-Hastings then updates the graph it built;
  • exact enumeration: a walk of the graph of one build into a lazy Hansei search tree (page hakaru10-exact);
  • the forward sampler: walks of the same graph that draw its active choices in address order and weigh its active observations, for likelihood weighting.

The last two share the graph and the node functions with the engine, but none of its incremental machinery, so each is an oracle of the kernel and of the incremental update (plan §6.10, C37). The tests below run the same models under all three.

test/construction-order: pass

H2. construction-check, the first check of #:check, builds the model, rebuilds it and redraws it, each from its own copy of one rng source. The rebuild must give the same graph (the kind, role, parents and scope of every node), the same values and the same LLs: a model that is not the same each time it runs fails it (plan §15, C35). The redraw draws every resampleable node in address order, from its distribution and its stored parents, and must give back every stored value, and the drawn LLs plus those of the active observations must give the trace's LL within 10⁻⁹. In address order an if_ first has the branch it does not take, whose choices are drawn and whose observations are not weighed, as ifnode builds it (Metropolis.hs:650-661). In 'upstream mode the LL is not bit-identical, because deactivation adds and then subtracts the inactive observations' LL; in 'extended mode the build recomputes it from the redraw's terms, in the redraw's order. So the redraw checks the draw order against the graph and the LL accounting. It runs the engine's construction code, so with the replays of hakaru10.scm it stands for an oracle of the node creation order (plan C18) that would not. #:check runs this check once per chain.

H5. Conditioning on a random choice is ill-typed upstream: observations are external to the model (Syntax.hs:38-42, P §2.3 l.412-421). exact-posterior walks the graph of a build, and the build raises conditioning.

cf. Examples1.hs:196-201. Upstream's types accept a distribution constructor that observes its argument, and its update keeps the observation the node was built with (Syntax.hs:251-252, Metropolis.hs:487-488), so its chain silently observes the first value (deviation 9). Here the engine's update raises conditioning when the observation changes, and so do the oracles, which recompute every node: enumeration, likelihood weighting, the reference evaluator of #:check and the kernel residual all agree with the chain.

(define observes-its-argument
  (do/monad
    (← x (dist bern 0.5))
    (dist (λ (xv) (condition xv (bern 0.8))) x)
    (return x)))

The graph is that of a build, which builds both branches of an if_, so a branch the drawn values leave inactive may raise a parameter error that enumeration, which skips the inactive branches, never meets. It is a dynamic condition, not a breach of the discipline: the build runs in 'extended mode, where it rejects the build (plan C22), and is retried until one completes. So the answer does not depend on what seed 17 draws first, for an error that rejects the build; another error of the build is raised, as in hakaru10.scm's invalid-inactive/branch (case B5). In nested-uniformly, when xs is the empty list, the inactive then branch draws from uniformly '(), an error; with the support of xs in either order the posterior is the same:

(define (nested-uniformly choices)
  (do/monad
    (← xs (dist uniformly choices))
    (if_ (lift pair? xs) (dist uniformly xs) (return 'none))))

and the retry still finds a breach that follows: nested-uniformly/ill-typed observes a choice after the branch, and raises conditioning with the support in either order, also when the first build is rejected.

(define (nested-uniformly/ill-typed choices)
  (do/monad
    (← xs (dist uniformly choices))
    (if_ (lift pair? xs) (dist uniformly xs) (return 'none))
    (← y (dist bern 0.5))
    (dist (condition y bern) 0.5)
    (return xs)))

A model that every build rejects has no graph, so the oracles raise construction after 1000 builds (plan §6.10). Below, the else branch is never taken, but in 'extended mode its normal is drawn as an inactive choice, from a mean that needs (car '()):

(define always-rejected
  (do/monad
    (← c (dist bern 0.5))
    (if_ #t
         (return c)
         (do/monad
           (← h (diracN (lift car '())))
           (← mu (diracN (lift cdr (pair h 1.0))))
           (dist normal mu 1.0)))))

Enumeration stops at #:max-paths leaves, with a support error: grass has 4 paths, more than 3, and as many as 4. A tree that model->search-tree builds with #:max-paths counts the leaves of all its explorations, so it can be explored once: the second exploration of grass's tree of 4 paths raises.

A walk of the graph forces the value of an active exit or Dirac node, as the engine's step does (deviation 11), so the oracles fail where mcmC does, whichever branch the graph's build took: in guarded-result the step that makes c false forces the deferred (car '()) of the else branch, which the graph's build leaves inactive, and the walks that take that branch raise the same Scheme error; guarded-result/mirror's build takes it, and raises there.

(define guarded-result
  (do/monad
    (← c (dist bern 0.5))
    (← r (if_ c (return 'ok) (diracN (lift car '()))))
    (return c)))

(define guarded-result/mirror
  (do/monad
    (← c (dist bern 0.5))
    (← r (if_ (lift not c) (return 'ok) (diracN (lift car '()))))
    (return c)))

A walk also writes each node's deactivation count before it recomputes the node, which reads it: in guarded-head the then branch's Dirac node, which is not the branch's result, applies car to '() whenever that branch is active, and the walks that take it raise, though the graph's build left it inactive; guarded-head/mirror's build takes it, and raises there.

(define guarded-head
  (do/monad
    (← c (dist bern 0.5))
    (let xs (lift (λ (cv) (if cv '(1) '())) c))
    (if_ (lift not c)
         (>> (diracN (lift car xs)) (return 'then))
         (return 'else))))

(define guarded-head/mirror
  (do/monad
    (← c (dist bern 0.5))
    (let xs (lift (λ (cv) (if cv '() '(1))) c))
    (if_ c (>> (diracN (lift car xs)) (return 'then)) (return 'else))))

A node that a switch activates may also keep the deferred value it got while inactive, when no update of the step recomputes it: the Dirac node of guarded-head/constant reads a constant, the inner exit of guarded-exit/constant an inner result that does not change, the root of guarded-root/constant has no update. The step forces such a value when its propagation ends, so it raises as the build of that branch active does, and as the walks that take the branch do, in both semantics, with or without #:check, and under the kernel residual: the chain's first sample is 'else, and a later step raises car's error. Upstream, which never reads these nodes, samples 'then and 'else about half the time each.
