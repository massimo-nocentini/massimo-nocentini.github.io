Examples

Section 3 of the paper Probabilistic Programming Language and its Incremental Evaluation (APLAS 2016, DOI 10.1007/978-3-319-47958-3_19) evaluates Hakaru10 on two realistic models; quoting design.txt l.454-460:

❝
The Hakaru10 tutorial might have given an impression that Hakaru10 tries so hard to preclude problematic behavior, by restricting conditioning and models, that one cannot do much interesting in it. In this section we briefly evaluate the expressiveness of the language on two realistic models.

Oleg Kiselyov

The two models are the Bayesian linear regression of the PPAML small problems collection (problem 4.1) and the population estimation of Milch et al.'s colored balls. To them the Hakaru10 page adds the bird migration problem of the PPAML challenge, which these tests run on synthetic data (the real data run is hakaru10-birds.scm, opt-in). Upstream's ColoredBalls.hs and Birds1.hs are transcribed definition by definition; the regression exists only in the paper, with its helpers in Birds1.hs.

Each model is a computation of the State monad that threads the chain, as upstream's Model a = MCMCM (SExp a) (Syntax.hs:82), written with do/monad as the Haskell is written with do: dist, diracN and if_ are models, and mcmC runs one under the MCMC engine. The oracles walk the trace graph of one build of the same model: exact enumeration (exact-posterior) and the forward sampler (likelihood-weighting, weighted-samples). So the same cballs-model is checked by MCMC, by likelihood weighting and, on a smaller urn, by exact enumeration, against a closed form; and the generative half of the bird and the regression models, run forward from seed 17, simulates the data that their conditioned versions then explain. The construction check rebuilds the model, which must give the same graph, values and log-likelihoods, and redraws its choices in address order, which must give back the values and the log-likelihood of the initial trace.

Nodes are created when a model runs, in bind order: do/monad top to bottom, and replicate/monad, traverse/monad, for-each/monad and fold/monad head first, upstream's sequence . replicate, mapM, mapM_ and foldM_: creation order is the topological order of the trace (design.txt l.791-794). A chain of if_ is built by fold-right over models, which create no node until the outermost one runs, and if_ delays its branches until it builds them, which reproduces upstream's foldr node for node: at 10000 samples the colored balls' histogram is upstream's own record (hakaru10-replay, X14).

C1. Population estimation, from Milch et al.'s BLOG: Probabilistic Models with Unknown Objects (Introduction to Statistical Relational Learning, MIT Press, 2007, pp. 373-398), example 1.1, as ColoredBalls.hs:1-13 quotes it:

❝
An urn contains an unknown number of balls--say, a number chosen from a Poisson or a uniform distributions. Balls are equally likely to be blue or green. We draw some balls from the urn, observing the color of each and replacing it. We cannot tell two identically colored balls apart; furthermore, observed colors are wrong with probability 0.2. How many balls are in the urn? Was the same ball drawn twice?

Milch et al.

The Hakaru10 page (index.html:111) calls it an elegant example of a model with an indefinite number of objects whose real identity is unobservable, a simplified population estimation, which in Hansei makes the case for the memoization of stochastic functions; the paper (design.txt l.519-520) notes that it motivated BLOG, being hard to implement in many probabilistic languages. Hakaru10 bounds the number of balls and pre-allocates one color per ball, which the unused branches marginalize (design.txt l.531-544); its footnote 5 (l.566-569) wishes for lazily instantiated branches instead. data Color = Blue | Green deriving (Eq, Show)

opposite_color :: Color -> Color
opposite_color Blue  = Green
opposite_color Green = Blue

-- Distribution for the observing of a ball, with the failure rate 20%
observed_color color =
  categorical [(color,0.8),(opposite_color color,0.2)]

maxBalls :: Int
maxBalls = 8

-- Create the prior for the max amount of balls that may be in the urn
balls_prior n = do
  balls <- sequence . replicate n $ dist uniformly (pure [Blue,Green])
  return $ M.fromList $ zip [1..] balls
-- Submodel: Given balls color and the observations, perform conditioning
balls_observe :: M.IntMap (SExp Color) -> [Color] -> Int -> Model ()
balls_observe balls obs nballs = mapM_ observe_ball obs >> return (pure ())
 where
  -- The same ball can be drawn twice as we return the drawn balls
  -- into the urn. A ball keeps its true color, no matter how many
  -- times it is drawn.
   observe_ball color = do
        b <- dist uniformly (pure [1..nballs])
        -- It is more efficient to create if statements, rather than
        -- create an SExp(IntMap Color).
        let observe i =
              let true_color = balls ! i in
              if_ ((== i) <$> b) $
                dist (color `condition` observed_color) true_color
        foldr observe (return (pure color)) [1..maxBalls]

-- The model takes a list of observations as an argument
cballs_model :: [Color] -> Model Int
cballs_model obs = do
  balls  <- balls_prior maxBalls
  nballs <- dist uniformly (pure [1..maxBalls])
  let obs_number i =
        if_ ((== i) <$> nballs) $ balls_observe balls obs i
  foldr obs_number (return (pure())) [1..maxBalls]
  return nballs

C3. The migration model is log-linear (BirdMigrationProblem.txt:32-33, 60-79): the potential of a flight from cell i to cell j is the dot product of the parameters with its four features, and the probability of the flight is its exponential, normalized over the cells within dₘₐₓ:

θₜ,ₜ₊₁(i, j) = exp βᵀxₜ,ₜ₊₁(i, j) Σⱼ′ exp βᵀxₜ,ₜ₊₁(i, j′)

Birds1.hs computes the numerators, phi (B1:82-85) and theta (B1:95-99), and leaves the normalization to categorical (Distribution.hs:87-91), which divides each weight by their sum; birdpos (B1:76-80) finds the bird where exactly one cell counts it:

-- where is the single bird on the day d of the year y
birdpos :: ObsData -> Year -> Day -> Maybe CellNum
birdpos obs y d = case [i | i <- [1..nCells], obs ! (y,d,i) > 0] of
  [i] -> Just i
  _   -> Nothing
phi :: Year -> Day -> CellNum -> CellNum -> Features -> [Double] -> Double
phi y d from to features bs = sum $ zipWith (*) fs bs
  where
    fs = [ realToFrac $ features ! (y, d, from, to, i) | i <- [1..nFeatures]]
-- multinomial (0; a,b,c) --> 0
-- multinomial (1,theta(i,1),,,theta(i,16))  -->
--     categorical [(1,theta(i,1)),(2,(theta(i,2))),... (16,theta(i,16))]
theta :: Year -> Day -> CellNum -> CellNum -> Features -> [Double] -> Double
theta y d from to features bs = exp $ phi y d from to features bs
(begin
  (define (phi fs bs) (fold + 0.0 (map * fs bs)))
  (define (theta fs bs) (exp (phi fs bs)))
  (define ((transitions features year day) n bs)
    (map (λ (j) (cons j (theta (features year day n j) bs))) (neighbors n)))
  (define (birdpos obs year day)
    (match/first
      (filter (λ (i) (positive? (obs year day i))) (iota n-cells 1))
      ((,i) i)
      (else #f))))

The checks: the weights of the flights from cell 6 on the first night, under β = (1, 2, 0.5, 1), come out of categorical as probabilities summing to 1 within 10⁻¹², each its weight over the total; staying has the features (0 0 0 2), so its weight is e²; birdpos finds the bird on days 1 and 2 (a count of 2 in one cell still is one cell) and not on day 3 (two cells) or day 4 (none).

Each count is a Poisson observation whose intensity is the number of birds in the cell, 0 or 1 with one bird (l.134-138, D:358-367): seeing no bird where it is has LL −1, seeing it once log 1 − 1 = −1, twice log(1/2) − 1; where it is not, seeing none has LL −0 and seeing any has −∞, which pins the bird to the cell where it was seen:

C4. The bird migration problem, quoting the Hakaru10 page (index.html:122-128):

❝
Bird migration problem was one of the Challenge problems of the DARPA PPAML (Probabilistic Programming for Advanced Machine Learning) Program. The goal was to estimate the model parameters from the set of bird migration observations over the period of thirty years. The migration model is a log-linear model with four parameters that gives the probability of a bird flying from cell i to cell j under given conditions.

Oleg Kiselyov

The problem statement (BirdMigrationProblem.txt:19-79) models the population as a collective graphical model: every night each bird flies from cell i to cell j with probability θ(i, j), and the birds counted in a cell are Poisson of the birds there. Its first data set has one bird on a 4x4 grid for 30 years of 20 days: each year the bird starts in the bottom-left cell and heads for the top-right one, a fully observed input-output HMM (l.103-105); the task is to estimate β₁, …, β₄ (l.179-182), whose prior may be the absolute value of a zero-mean Gaussian of sd 10, the features being coded so that every parameter should be non-negative (l.457-464). Birds1.hs:50-74 is the model of Sasaki Shoichiro's 2018 bachelor thesis, which, the page says, closely reflects the specification:
