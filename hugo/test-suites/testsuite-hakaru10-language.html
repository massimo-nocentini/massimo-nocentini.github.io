Introduction

Quoting from Embedded probabilistic domain-specific language Hakaru10:

❝
This system description paper introduces the probabilistic programming language Hakaru10, for expressing, and performing inference on (general) graphical models. The language supports discrete and continuous distributions, mixture distributions and conditioning. Hakaru10 is a DSL embedded in Haskell and supports Monte-Carlo Markov Chain (MCMC) inference. Hakaru10 is designed to address two main challenges of probabilistic programming: performance and correctness. It implements the incremental Metropolis-Hastings method, avoiding all redundant computations. In the presence of conditional branches, efficiently maintaining dependencies and correctly computing the acceptance ratio are non-trivial problems, solved in Hakaru10. The implementation is unique in being explicitly designed to satisfy the common equational laws of probabilistic programs. Hakaru10 is typed; specifically, its type system statically prevents meaningless conditioning, enforcing that the values to condition upon must indeed come from outside the model.

Oleg Kiselyov

In Scheme a model is a State computation (S:82, Model a = MCMCM (SExp a), MCMCM a = State MCState a, M:200) written with do/monad, as in Syntax.hs: its state is the chain, and running it builds the trace graph, dist, diracN and if_ each adding their nodes. The same grass model below is sampled by incremental Metropolis-Hastings (mcmC), enumerated exactly over its trace graph into a Hansei search tree (exact-posterior) and sampled forward over the same graph with likelihood weights (likelihood-weighting).

(define ((nor strength-x strength-y noise) x y)
  (bern (- 1.0
           (* (* (nnot (- 1.0 strength-x) x) (nnot (- 1.0 strength-y) y))

Branching models

Quoting P §2.2 l.330-347:

❝
Hakaru10 can express not only 'straight-line' but also branching models. An example is a simple mixture model [mixng] whose distribution is the mixture of normal and gamma distributions, with the random variable x determining the proportion of the mixture. [...] The mixng program is the first betraying Model being not quite a monad. The variable x is not actually of the type Double, as one might have thought. [...] As should be apparent from the use of Applicative operator <$>, which is just fmap, Model a is something like M (A a) where M is a monad but A is an applicative.

Oleg Kiselyov

In Scheme the applicative of SExp is lift (with pair, collect and the sexp+ family for the Num instance, S:99-135), while <$> and <*> are those of the Model monad (B1:52 abs <$> dist normal 0 10), and the branch is if_, whose test must be a boolean stochastic expression:

(define mixng
  (do/monad
    (← x (dist normal 0.0 1.0))
    (if_ (lift (λ (xv) (> xv 0.0)) x)
         (dist normal 10.0 2.0)
         (dist gamma 3.0 (/ 1.0 3.0)))))

(define (mixng′* bern)
  (do/monad
    (← x (dist bern 0.5))
    (if_ x (dist normal 10.0 2.0) (dist gamma 3.0 (/ 1.0 3.0)))))

Both should give the same distribution, as should the interleaving of 2500 samples of each component (P l.361-366; replay case X12).

Conditioning

Quoting P §2.3 l.393-398 and l.418-421:

❝
As biased coin code demonstrates, in Hakaru10 conditioning may only be applied to distributions. One may think that (c1 `condition` bern) creates a new distribution out of bern, with the singular value c1. Conditioning on arbitrary boolean formulas is fraught with peril, both theoretical and practical, degenerating MCMC algorithm into the inefficient rejection sampling. [...] Here, we attempted to condition bern on the random choice within the model. This is not allowed: observations must be external to the model. In [20], this semantic condition was a merely a coding convention, whose violation manifested as a run-time exception. In Hakaru10, the violation is a type error.

Oleg Kiselyov

(define (biased-coin c1 c2)
  (do/monad
    (← b (dist beta 1.0 1.0))
    (dist (condition c1 bern) b)
    (dist (condition c2 bern) b)
    (return b)))

Why distributions: the temperature model of P l.653-673 observes 25 from normal tempr 0.1, an event of probability zero; what can be asked is how likely 25 is under that distribution, its density, which the observed node contributes to the trace's log-likelihood. Scheme has no static types, so the static discipline of Syntax.hs becomes run-time checks (deviation 9, in the style of Ścibior et al. [20]), each an (exn hakaru10) condition whose kind property says what was violated (case test/language/errors):

  • observations are external (S:38-42, S:174-193): condition of a stochastic expression, of a model, or of a Scheme value holding either raises conditioning, and so does an observation that a distribution constructor computes from its argument, at the update that changes it;
  • only resampleable distributions are conditioned, never twice (S:185-193, E:180-186): conditioning;
  • SExp is not a monad (S:118, P l.739-747): a model answered by a lifted function, at the build or at an update, raises construction;
  • a model is a type of its own (S:82, plan §15 C32): a model in an SExp position (an argument of dist, the result, inside a Scheme value) or a value where a model is expected (mcmC's argument, a branch of if_) raises construction; procedures are plain values (S:107 Val f);
  • the test of if_ is SExp Bool (S:275): a non-boolean raises branch;
  • lexical scoping, implicit upstream (deviation 10): a node of another chain raises construction, a node escaping its branch, as a parent or as the result of another branch or of the model, branch;
  • the static kind of a node (M:46-60; deviation 10): a constructor that changes kind raises construction.

Implementation

Quoting P §4.1 l.723-747:

❝
Hakaru10 represents the trace -- random variables of the model and their dependencies -- as a directed acyclic graph (DAG). Each node (vertex) in the graph stands for one random variable (whose value can be sampled and resampled) or an observed variable, whose value cannot be resampled. There are also computational nodes, representing 'samples' from the dirac distribution. [...] A Hakaru10 model has the type type Model a = MCMCM (SExp a) It is a computation that constructs the trace graph. MCMCM is a monad, but SExp is not. It is an applicative [13]: it lets us construct new graph nodes, without looking at their values. [...] The fact that SExp is not a monad is significant: the current node values cannot influence the graph construction. Therefore, after the graph is built, its structure does not change. All dependencies among nodes can be computed once and for all.

Oleg Kiselyov

In (aux hakaru10 engine) the trace is a chain, a vector of node records indexed by creation order (the address, replacing Memory.hs); a node's dynamic state is an immutable nstate record (value, log-likelihood, distribution, timestamp) replaced as a whole, as Mem.modify_ref does. Model a = MCMCM (SExp a) is a State monad threading the chain (plan §15 C34), run once per build by build-chain (M:872-880 initial_step'), whose construction functions mirror Syntax.hs and Metropolis.hs by name (create-node, with-node-ctor, to-node, ifnode, ...); an SExp is a node, an nt (leaves and a function: S:85-116's NT) or any other value (Val). For the grass model the graph has the three nodes of P's Fig. 1 (case test/language/graph/grass).

Incremental recomputation (P §4.2 l.765-800): resampling a node enqueues its dependents; propagate! (M:293-317) pops the queue in increasing address order, a binary heap, because

❝
The fact that Hakaru10 models are acyclic and Hakaru10 programs are declarative (with no mutations) lets us avoid the topological sort and rely on the 'creation times' of trace nodes. A node can only depend on those constructed before it.

Oleg Kiselyov

Creation order is therefore load-bearing (plan C18): a node is created when the model that makes it runs, in bind order, do/monad top to bottom and the traversals head first (plan §15 C35; see the embedding notes).

The Dirac distribution (P §4.3 l.801-843): a Dirac node is a pure computation, recomputed whenever a parent changes, its log-likelihood staying 0, so a proposal is extended to all dependent Dirac nodes and the unit laws hold by construction (laws suite). diracN of a node answers the node itself, shared (S:164-168).

Branching (P §4.4 l.844-869):

❝
Hakaru10 avoids any modifications to the graph structure during the trace update. It compiles both if-branches when constructing the initial graph. [...] Updating the nodes in the inactive branch, whose values will be ultimately ignored, is not good for performance. Therefore, we mark the nodes in the non-current branch as inactive, and delay their updates until they are activated. Thus each node, along with its current value, LL and the distribution also keeps the inactivation count.

Oleg Kiselyov

if_ (S:275-279) builds the entry (the test, always a new Dirac node); ifnode (M:641-686) then builds the inactive branch first, deactivates its nodes (deactivate, M:696-717, which takes the observed nodes' LL back), the active branch, and the exit node, whose value is the active branch's result (update-exit, M:778-794). When the entry's value changes, update-entry (M:760-775) moves the counts and the observed LL between the branches and replays the updates delayed while a node was inactive.

One MH step, transit! (M:908-945): pick an active resampleable node uniformly (M:956-977), resample it from its own distribution, propagate, and accept with the log ratio of M:929-934, where Δ is the change of the trace's log-likelihood accumulated by the updates, S the number of resampleable nodes and c and c′ the change of their active count before and after the step (the derivation is the note M:1039-1089):

log α = Δ − ( fwd − bwd ) + log S + c S + c′

A rejected step restores the whole state from a journal of undo thunks, except the random generator (M:904-906). The engine's source:

Embedding notes

  • Models are State computations (plan §15 C32, C33). A model is a value of the State monad of (aux category state), Model a = MCMCM (SExp a) (S:82), whose state is the chain: dist, diracN and if_ are models, lift, pair, collect and condition are pure, and return makes no node (S:197, S:211-214). Running a model again makes fresh nodes, so there is no accidental sharing (P l.175-179) and sharing comes only from binding a name (S:53-73). Models compose by binding one another ((phierN′ 9 x 1.) in condhier) and are values (phierN folds a model transformer). The engine's construction functions keep upstream's names, each a State action (create-node, M:404-419; with-node-ctor, S:218-228; ifnode, M:641-686).
  • Bind order is creation order (plan §15 C35). Node creation order is the topological order of propagation and fixes the random draws of a replay. A node is created when the model that makes it runs, in bind order: do/monad top to bottom, and fold/monad, traverse/monad (mapM), for-each/monad (mapM_) and replicate/monad head first. Building a model creates no node, so a model may be built anywhere, in an argument position or inside map: the order is the binds', as ordered-pair shows (case test/language/applicative).
  • if_ delays its branches (plan §15 C36). if_ is syntax over the engine's if_* (S:275-279): its branch expressions are evaluated when ifnode builds each branch, inside the branch's scope and, for the inactive one, under lazy lifting, the stand-in for Haskell's non-strict arguments on which deviation 11 relies. A branch must be a model, (return v) for a value: (if_ c 1 2) raises construction when the branch is built. Being syntax, if_ is used inside a λ where a procedure is needed, as in the foldrs of the colored balls.
  • Running a model several times (plan §15 C35). A model may run several times: the retries of the initial trace (M:882-891), the rebuild of #:check, the trace graph of the oracles. A Scheme effect that must happen once per run belongs inside a bind, after it: the first clause of a top-level do/monad is evaluated once, when the definition is. That is harmless for dist, diracN, if_ and return, which only build models; an SExp computed there, such as (lift car '()), is computed at once (deviation 11). The counters of case B4′ run their effect per run with (>>= (return #f) (λ (_) (add1! k) (return k))), the models of case L5 after the bind of the node they capture, with (let _ (set! captured x)).
  • A clause that is not a model. A bare clause of do/monad must be a model: one that is not, such as (add1! k) between two binds, fails with CHICKEN's record-type error when the model runs, a Scheme error, not a construction one (case L5). Bind it with (let _ ...) instead.
  • The static discipline is the build (plan §15 C37). SExp is applicative, not a monad (S:118), and if_ builds both branches (M:650-661), so one build is the whole trace graph, and it checks the static discipline (deviations 9, 10) as it goes, but for what only a later value can show, which the updates and the oracles' recomputation check: a node's kind, the boolean test of if_, a lifted function's answer, and an observation that a distribution constructor computes from its argument (case L5). exact-posterior, model->search-tree, weighted-samples and likelihood-weighting walk the graph of one 'extended build (plan §6.10), reusing none of the incremental machinery. That assumes a model whose Scheme code does not branch on build-time values, which nothing catches: the rebuild of #:check draws the same values from a copy of the same source, so it takes the same branch, and catches only a construction that depends on state outliving a run (the counters and switching of case B4′).
  • condition. (chicken condition) exports a procedure of the same name: import it as (except (chicken condition) condition), as this file does.
  • Stochastic memoization (P §3 l.531-544, footnote 5 l.566-569, CB:41-44) becomes pre-allocation, as upstream's own balls_prior (CB:43, sequence . replicate): (replicate/monad n m) runs m n times, in order, before the if_s that use its nodes, which so belong to no branch; balls-prior keys them by ball in an alist.
  • Sampling. mcmC, mcmC-fold (constant memory) and mcmC§ (an (aux stream) stream: take§, §->list, car§, cdr§) take the keys #:seed (17, as M:858), #:rng (an rng source, used as is), #:semantics ('upstream or 'extended, see the semantics suite) and #:check (the reference evaluator on every step, or on the first n). There is no burn-in nor thinning: drop the samples, as upstream does.

The deviations, each tagged in the source with its number:

  1. the exit's update returns the node unchanged when neither the entry nor the active result is newer, where upstream fails (M:788-792; case S20 if/shared-inactive);
